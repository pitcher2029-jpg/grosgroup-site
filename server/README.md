# Обработчик заявок с сайта

Принимает форму «Оставить заявку» (`POST multipart/form-data`), проверяет поля, отсекает ботов,
доставляет заявку по настроенным каналам и сохраняет резервную копию на диск.
Node.js 22+, без зависимостей.

```
server/
  http.mjs   HTTP-сервер (точка входа)
  lead.mjs   проверка, антиспам, доставка, резервная копия
  smtp.mjs   SMTP-клиент: SSL 465 или STARTTLS 587, AUTH PLAIN, вложения
  test/      node --test server/test/*.test.mjs
```

## Запуск

```sh
node server/http.mjs          # слушает 127.0.0.1:8787, путь /api/lead
```

Сервер ставится за nginx (`location /api/lead` → `proxy_pass http://127.0.0.1:8787`) и
запускается службой systemd — шаблоны в `deploy/`. На сайте в `assets/js/main.js`
задать `CONFIG.endpoint = '/api/lead'`.

## Переменные окружения

Нужен хотя бы один канал доставки; без каналов сервер отвечает 500 `not_configured`.
Пароли и токены хранятся в файле окружения службы с правами 600, не в репозитории.

| Переменная | Назначение |
|---|---|
| `PORT`, `HOST` | адрес сервера, по умолчанию `8787`, `127.0.0.1` |
| `LEAD_PATH` | путь приёма, по умолчанию `/api/lead` |
| `ALLOW_ORIGIN` | домен сайта для CORS, если обработчик на другом домене (`https://grosgroup.ru`) |
| `TRUST_PROXY` | `1` — брать IP клиента из `X-Real-IP` / `X-Forwarded-For` (только за своим nginx) |
| **Почта** | |
| `SMTP_HOST`, `SMTP_PORT` | сервер и порт: 465 — SSL, 587 — STARTTLS. Яндекс 360: `smtp.yandex.ru:465` |
| `SMTP_USER`, `SMTP_PASS` | ящик-отправитель и пароль приложения |
| `MAIL_FROM` | отправитель, по умолчанию `SMTP_USER`: `GROSGROUP <site@grosgroup.ru>` |
| `MAIL_TO` | получатели через запятую |
| `SMTP_SECURE` | `1`/`0` — принудительно SSL или STARTTLS, иначе по порту |
| **Telegram** | |
| `TG_BOT_TOKEN`, `TG_CHAT_ID` | бот и чат (группа — отрицательный id) |
| **CRM** | |
| `WEBHOOK_URL`, `WEBHOOK_TOKEN` | POST JSON заявки (без файлов, только имена и размеры), `Authorization: Bearer` |
| **Резервная копия** | |
| `LEAD_STORE_DIR` | каталог: `leads.jsonl` + `files/<номер заявки>/`, права 600 |

Каналы работают независимо: заявка считается принятой, если дошла хотя бы по одному.
Если все каналы отказали, но резервная копия записана, клиент видит успех, а в журнал
пишется `DELIVERY_FAILED` — заявку забирают из `LEAD_STORE_DIR`.

## Ответы

| Код | Тело | Когда |
|---|---|---|
| 200 | `{ok:true}` | принято; также ловушка для ботов и отправка быстрее 3 с — без доставки |
| 400 | `{error:"invalid", fields:{…}}` | поля не прошли проверку (тексты ошибок по-русски) |
| 400 | `{error:"bad_form"}` | тело не разбирается как форма |
| 404 / 405 | | чужой путь / не POST |
| 413 | `{error:"too_large"}` | тело больше 52 МБ |
| 429 | `{error:"rate_limited"}` | больше 8 запросов с одного IP за 10 минут |
| 500 | `{error:"not_configured"}` | не настроен ни один канал |
| 502 | `{error:"delivery_failed"}` | все каналы отказали, резервной копии нет |

Ограничения (`LIMITS` в `lead.mjs`): до 5 файлов по 10 МБ; форматы pdf, doc, docx, xls, xlsx,
csv, txt, png, jpg, jpeg, dwg, zip. Поля проверяются по тем же правилам, что и в браузере.

## Персональные данные

- Заявка содержит ПДн (имя, телефон, почту). Сервер и резервная копия — в России (152-ФЗ, ст. 18 ч. 5).
- Доставка в Telegram — трансграничная передача ПДн: до включения канала нужно отдельное уведомление
  Роскомнадзора и упоминание в политике. Без этого используйте почту на российском сервисе и CRM.
- В заявке фиксируется время согласия (`consentAt`); резервные копии удаляются по сроку,
  указанному в политике обработки ПДн.

## Проверка

```sh
node --test server/test/*.test.mjs
```

Тесты поднимают поддельные SMTP и Telegram на 127.0.0.1 и не ходят в сеть.
